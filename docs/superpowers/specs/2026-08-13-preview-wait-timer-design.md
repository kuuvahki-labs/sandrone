# 预览等待计时设计

## 目标

订阅预览和文件预览在请求处理中显示真实的已等待时间，让用户能判断一次预览已经等待多久，同时不伪造进度或剩余时间。

## 用户界面

- 订阅预览与文件预览统一显示“正在处理”。
- 请求开始后不足一秒时只显示“正在处理”。
- 从第一秒开始显示“正在处理 · 已等待 N 秒”。
- 首次加载和保留旧结果的手动刷新使用相同文案与展示方式。
- 删除现有“以已保存的……定义为准”说明，不再区分“计算”“生成”和“刷新”。
- 不显示百分比、处理阶段或预计剩余时间。

## 状态与计时

共享预览 Hook 负责记录当前请求的开始时间，并按秒暴露已等待时长。显示值根据开始时间与当前时间计算，不将定时器触发次数当作经过时间，以免浏览器后台降频导致计时漂移。

每次首次加载或手动刷新都重新从零开始。请求成功、失败、资源切换、资源清空或组件卸载时停止计时并归零。过期请求不能覆盖新请求的计时状态。

两个预览页面复用同一个轻量状态组件，避免文案、布局和无障碍语义分叉。状态文本使用礼貌的动态播报，秒数更新不抢占用户焦点。

## 错误处理

计时不改变请求、缓存和错误处理。失败后沿用现有错误卡片，停止显示等待状态；刷新失败时保留已有预览及现有失败语义。

## 验证

- 共享 Hook 覆盖首次加载、手动刷新、完成、失败、资源切换和卸载时的计时生命周期。
- 订阅预览与文件预览页面验证相同文案，以及有无旧预览时的展示位置。
- 运行相关窄测，并在交付前运行前端类型检查、lint、完整测试和仓库范围匹配门禁。
