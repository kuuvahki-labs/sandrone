# 文件配置内容布局设计

## 目标

让普通文件与配置文件保持一致的自上而下阅读结构，并明确模板、节点来源、
自适应分组和最终配置正文之间的关系。

## 信息架构

普通文件保持：

1. 基础信息
2. 文件内容
3. 文件处理

结构化配置文件调整为：

1. 基础信息
2. 配置内容
3. 文件处理

“配置内容”内部按生成依赖排列：

1. 配置模板
2. 节点来源
3. 自适应分组
4. 基础配置内容
5. 代理组、规则集和路由规则

配置模板位于其所修改内容之前；节点来源紧邻依赖它的自适应分组；最终配置
正文放在生成工具之后，支持用户按“先生成、后检查和微调”的方向操作。

## 界面改动

- 为结构化配置工作台增加可见的“配置内容”顶层标题。
- 将“配置模板”移动到“节点来源”之前。
- 将“配置明细”标题删除，避免与新的顶层标题重复。
- 将纯文本基础配置区从“基础配置”改名为“基础配置内容”。
- 原始配置模式沿用同一“配置内容”语义，不改变数据格式或编辑行为。

## 行为与兼容性

本次只调整展示顺序、视觉层级和文案，不改变模板应用、节点预览、自适应生成、
表单序列化或后端配置格式。

## 验证

- 组件测试验证各区域的可访问名称和 DOM 顺序。
- 集成测试验证模板应用、自适应生成和原始配置模式行为不变。
- 运行 Web 类型检查、lint、全量测试和生产构建。
